# R50 — 51-round security audit + hardening library

**Audited:** 2026-04-26
**Scope:** every Python source file under `src/aria/` (179 828 LoC), every
deployed aiohttp / FastAPI service, the cFS bridge C source, the Docker
deploy stack, and the dependency tree.
**Tools:** bandit ≥1.9 (full repo scan), pip-audit (PyPI advisory lane),
ruff (lint + style), defusedxml (XXE), pip-tools (lockfile), CycloneDX
(SBOM), grep-based gitleaks. **No paid scanners — every check is
reproducible from a clean clone.**

This document is the operator-readable transcript of the audit: the 51
defence rounds we walked, the open-source signal that fed them, the
breach class each round closes, and the regression net that proves the
fix is wired in.

---

## 1. Executive summary

| Phase | Before | After |
|-------|--------|-------|
| Bandit HIGH findings | 2 | 0 |
| Bandit MEDIUM findings | 47 | 0 (42 documented `# nosec` annotations on intentional patterns — bound-param SQL, dev-default binds, env-gated pickle) |
| pickle.load on untrusted data | 2 sites unguarded | env-gated; alphanumeric-only path; documented RCE warning |
| XML parsing without XXE defence | 2 sites | both routed through `defusedxml`-backed `safe_xml_*` |
| `urllib.urlopen` without SSRF guard | 4 sites | wrapped in `safe_open_url` (private-IP block, response cap, allow-list) |
| `from_pretrained()` without revision pin | 4 sites | revision pinned via env or config; warn-on-miss |
| `torch.load(weights_only=False)` | 1 site | `weights_only=True` |
| aiohttp services without security headers | screener + advisor | both wrapped in `harden_aiohttp_app(...)` |
| Dependency lockfile | missing | `requirements-lock.txt` generated by `pip-compile` |
| SBOM | missing | `aria.cdx.json` (CycloneDX 1.5) |
| Trojan-source bidi chars in source | 1 file | rewritten as `\uXXXX` escape sequences |

The aria-core security surface now has a single import, `aria.security.guard`,
that is wired into every aiohttp service and every outbound HTTP call.
Future endpoints inherit the defences automatically through one call:
`harden_aiohttp_app(app, config=...)`.

## 2. The 51 rounds

Each round is one threat → one verdict → one piece of evidence.
Numbered by thematic block, not by chronology.

### Block A — Authentication, authorisation, key management (R1–R10)

| # | Threat | Verdict | Evidence |
|---|--------|---------|----------|
| R1 | API-key timing oracle | PASS | `service.py:113` — `hmac.compare_digest` |
| R2 | Admin-token escalation via verb tampering | PASS | dedicated `X-ARIA-Admin-Token` header + method allow-list |
| R3 | Key-rotation race window | PASS | tenants.py rotation grace; tests cover overlap |
| R4 | Tenant impersonation via key collision | PASS | 32-byte random keys (`secrets.token_hex`) |
| R5 | Session token theft (Storm-0558 class) | PASS | server-side opaque tokens, idle TTL, revocation |
| R6 | Weak hash for security (SHA1) | **FIXED** | `corpus_builder.py` UID switched to SHA-256 |
| R7 | HMAC for webhook signature | PASS | alerts/service.py uses HMAC-SHA256 |
| R8 | RNG quality (random vs secrets) | PASS | repo-wide grep — only `secrets` module used for keys |
| R9 | TLS termination + HSTS | PASS | Caddy auto-TLS; `Strict-Transport-Security` added by guard |
| R10 | Admin double-token (Snowflake-class breach 2024) | NEW | `mfa_admin_check` — long token + TOTP-style OTP, env-driven |

| Snowflake / UNC5537 | 2024 | Credential stuffing — no MFA | `mfa_admin_check` (long token + OTP); per-tenant rate limit | full |
| Twilio Authy | 2024 | Unauthenticated API endpoint | Every `/v1/screen*`, `/v1/advise*` requires `X-ARIA-Token`; method guard | full |
| Polyfill.io | 2024 | Hostile maintainer push to CDN-served JS | `revision=` pin on HF + lockfile + SBOM; no third-party CDN | full |
| XZ Utils (CVE-2024-3094) | 2024 | Multi-year maintainer compromise | `trust_remote_code=False`; revision pin; SBOM diff in CI | full |
| Dell unauth API | 2024 | Endpoint missing auth | `make_method_guard_middleware` + auth check per route | full |
| AT&T Snowflake leak | 2024 | Same as Snowflake | Same as Snowflake row | full |
| Capital One (replay) | 2019 (still relevant) | SSRF → AWS metadata 169.254.169.254 | `validate_outbound_url` blocks 169.254.0.0/16 | full |
| Log4Shell (CVE-2021-44228) | 2021 (replay) | Reflection-driven JNDI lookup | Python — n/a; `sanitise_for_log` would refuse bidi/control chars in any case | n/a |

## 4. The hardening library — `aria.security.guard`

A single import surface (~470 LoC, no third-party runtime deps beyond
`defusedxml`) encapsulates every defence the audit produced:

| Symbol | Defence |
|--------|---------|
| `validate_outbound_url`, `safe_open_url` | SSRF + response-size cap |
| `safe_xml_fromstring`, `safe_xml_parse` | XXE / billion-laughs |
| `safe_json_loads` | depth + size cap |
| `safe_zip_extract`, `safe_zip_open` | zip-slip + decompression bomb |
| `safe_pickle_block` | refuse pickle; force structured-format migration |
| `safe_yaml_load` | always `safe_load` |
| `sanitise_for_log` | CRLF / bidi / NUL strip |
| `mfa_admin_check` | Snowflake-class double-token gate |
| `make_security_headers_middleware` | OWASP headers (HSTS, CSP, frame-options, …) |
| `make_body_size_middleware` | 413 on oversize Content-Length |
| `make_method_guard_middleware` | verb allow-list |
| `make_request_id_middleware` | mint + echo, refuse malformed |
| `harden_aiohttp_app(app)` | one-call wiring of all four middlewares |
| `runtime_check_environment()` | boot-time fail-closed configuration audit |

Every helper is **fail-closed** by default.  An operator who wants to
relax a defence at one call site can pass kwargs (e.g.,
`allowed_schemes=("https", "http")`); they cannot relax it at the
library level.

The library is wired into:

* `aria.products.conjunction_screener.service.create_app` (R47)
* `aria.products.cubesat_deorbit.service.create_app` (R47)
* `aria.cognitive.rag.ntrs_client._get` (R15)
* `aria.notifications.alerter.WebhookSink.send` (R15)
* `aria.physics.gravity.ephemeris.HorizonsRestEphemeris.get_state` (R15)
* `aria.physics.gravity.ephemeris.KernelManager.download_kernel` (R15)
* `aria.dsremo.ingest.xtce_parser.parse_xtce` (R13)
* `aria.integrations.nasa_public.dsn_now.parse_dsn_xml` (R13)

## 5. Reproducible audit trail

```bash
# ── Static analysis ──────────────────────────────────────────────
bandit -r src/aria/ -ll              # severity ≥ medium, low confidence excluded
ruff check src/                       # F + B + S + UP + I rule-sets
pip-audit --strict                    # PyPI advisory database

# ── Supply-chain artefacts ───────────────────────────────────────
pip-compile pyproject.toml -o requirements-lock.txt
cyclonedx-py environment -o aria.cdx.json
shasum -a 256 requirements-lock.txt aria.cdx.json > sha256.txt

# ── Defence regressions ──────────────────────────────────────────
pytest tests/integration/test_security_guard.py        # 34 tests, all green
pytest tests/integration/test_conjunction_screener_service.py
make smoke                                              # 158 tests, < 5 s
```

The 34 guard regressions cover every item in §2 that received a fix
verdict.  CI runs them on every push.

## 6. Residual risk

Items NOT closed by R50 are kept here so future audits don't re-discover
known-open holes:

* **WebSocket auth (R28)** — the dashboard event stream remains anonymous on
  the read path; mutating commands all require auth.  Fix: gate WS upgrade
  on a session cookie before issuing the handshake response.
* **Dependabot (R42)** — advisory-only `pip-audit` runs in CI but no
  auto-PR pipeline.  Operator must enable Dependabot in the GitHub UI; the
  receiving repository is in their account, not ours.
* **DO-178C-class formal review of cFS C source** — bandit doesn't analyse
  C; covered separately in `cfs_bridge/STATUS_AND_NEXT.md`.
* **Operator-side MFA, VPN posture, on-call rotation** — outside aria-core's
  trust boundary; documented in `docs/ops/RUNBOOK.md`.

Future audit (R75 target) will additionally cover: CCSDS link-layer auth,
TPM-rooted attestation in cFS, and post-quantum migration of audit-log
hash chain to SHA3-512.
